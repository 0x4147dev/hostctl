#+TITLE: Hostctl
#+AUTHOR: 0x4147dev
#+SUBTITLE: A useful tool to manage /etc/hosts entries during pentest engagements

* Introduction

  =hostctl= is a simple and useful tool for pentesters to quickly add,
  remove, and track entries in the =/etc/hosts= file, without having
  to edit it manually.

  Every entry added by =hostctl= is silently tagged with a marker
  comment (e.g. =# hostctl:acme-2026=), so you can group entries by
  engagement or client and, most importantly, clean them all up in
  one shot when the job is done — no more leftover target IPs and
  domains sitting forgotten in your hosts file.

* Features

  - Add and remove one or more domains at once
  - Tag entries by engagement/client with =-t/--tag=
  - List everything =hostctl= has added, filterable by tag
  - Bulk-clean all entries for a tag, or everything, with one command
  - Surgical =remove=: only strips the matching domain(s), never
    touches other domains sharing the same line
  - Automatically merges new domains into an existing line for the
    same IP + tag, instead of creating duplicate lines
  - Validates IP addresses before writing anything
  - Automatic backup (=/etc/hosts.bak=) before every write
  - Atomic writes (temp file + rename), so a crash mid-write can't
    corrupt =/etc/hosts=

* Requirements

  - Python 3
  - Root privileges (writing to =/etc/hosts= requires =sudo=)

* Installation

  #+begin_src sh
git clone https://github.com/0x4147dev/hostctl.git
cd hostctl
chmod +x hostctl.py
  #+end_src

  Optionally, install it globally:

  #+begin_src sh
sudo cp hostctl.py /usr/local/bin/hostctl
sudo chmod +x /usr/local/bin/hostctl
  #+end_src

* Usage

  #+begin_src 
usage: hostctl [-h] {add,remove,list,clean} ...

Manage /etc/hosts entries, with per-engagement tagging.

positional arguments:
  {add,remove,list,clean}
    add                 Add one or more host entries
    remove              Remove one or more host entries by domain
    list                List hostctl-managed entries (optionally by tag)
    clean               Bulk-remove hostctl-managed entries (by tag or all)

options:
  -h, --help            show this help message and exit
  #+end_src

** Add a host entry

   #+begin_src 
usage: hostctl add [-h] [-t TAG] ip domains [domains ...]

positional arguments:
  ip                    IP address (e.g. 10.10.10.10)
  domains               One or more domain names (e.g. target.local api.target.local)

options:
  -h, --help            show this help message and exit
  -t TAG, --tag TAG     Tag this entry with an engagement/client name (e.g. acme-2026)
   #+end_src

   Examples:

   #+begin_src sh
# Single domain, no tag
sudo hostctl add 10.10.10.10 target.local

# Multiple domains on the same IP, in one call
sudo hostctl add 10.10.10.10 test.com data.test.com

# Tagged for a specific engagement
sudo hostctl add 10.10.10.10 acme.local api.acme.local -t acme-2026
   #+end_src

   If a domain is already present anywhere in the file, it is skipped
   individually (the rest of the domains are still added). Adding more
   domains later for the same IP and tag merges them into the existing
   line instead of creating a duplicate one.

** Remove a host entry

   #+begin_src 
usage: hostctl remove [-h] domains [domains ...]

positional arguments:
  domains     Domain name(s) to remove

options:
  -h, --help  show this help message and exit
   #+end_src

   Example:

   #+begin_src sh
sudo hostctl remove target.local api.acme.local
   #+end_src

   Only the matching domain(s) are stripped from their line. If other
   domains remain on that line, the line (and its tag) is preserved;
   the line is dropped entirely only when no domains are left on it.

** List managed entries

   #+begin_src 
usage: hostctl list [-h] [-t TAG] [-a]

options:
  -h, --help         show this help message and exit
  -t TAG, --tag TAG  Only list entries with this tag
  -a, --all          Show the full hosts file, not just hostctl-managed entries
   #+end_src

   Examples:

   #+begin_src sh
# List everything hostctl has added
sudo hostctl list

# List only entries for a specific engagement
sudo hostctl list -t acme-2026

# Show the whole /etc/hosts file
sudo hostctl list -a
   #+end_src

** Clean up after an engagement

   #+begin_src 
usage: hostctl clean [-h] (-t TAG | -a)

options:
  -h, --help         show this help message and exit
  -t TAG, --tag TAG  Remove all entries with this tag
  -a, --all          Remove every hostctl-managed entry, regardless of tag
   #+end_src

   Examples:

   #+begin_src sh
# Wipe every entry tagged for a finished engagement
sudo hostctl clean -t acme-2026

# Wipe every entry hostctl has ever added, keep system defaults untouched
sudo hostctl clean -a
   #+end_src

   Entries not managed by =hostctl= (e.g. =localhost=, manually added
   lines) are never touched by =clean=.

* Typical pentest workflow

  #+begin_src sh
# Start of engagement
sudo hostctl add 10.10.10.10 acme.local api.acme.local -t acme-2026
sudo hostctl add 10.10.10.20 vpn.acme.local -t acme-2026

# Check what you've added so far
sudo hostctl list -t acme-2026

# End of engagement: clean up in one shot
sudo hostctl clean -t acme-2026
  #+end_src

* Notes

  - The script must be run with =sudo=, otherwise it exits with an
    error (=[!] Error: run the script with sudo!=).
  - Every write is preceded by a backup at =/etc/hosts.bak=.
  - This tool only targets Unix-like systems (=/etc/hosts= is
    hardcoded as the path).
